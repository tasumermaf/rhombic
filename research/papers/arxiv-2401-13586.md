# Instruction Fine-Tuning: Does Prompt Loss Matter?

> arXiv: [2401.13586](https://arxiv.org/abs/2401.13586) · [link](https://arxiv.org/html/2401.13586v2/)

**Authors:** Mathew Huerta-Enochian, Seung Yong Ko  
**Venue:** arXiv  
**Date:** 2024-01-24  
**Category:** cs.LG  
**Tags:** nemotron-engineering, prompt-loss-weight, sft, loss-masking

## Abstract

We present a novel study analyzing the effects of various prompt loss token weights (PLW) for supervised instruction fine-tuning (SIFT). While prompt-masking (PLW = 0) is common for SIFT, some fine-tuning APIs support fractional PLWs and suggest that using a small non-zero PLW can help stabilize learning when fine-tuning on short-completion data. However, there has never been a study confirming this claim, and OpenAI, a major cloud-based SIFT provider, recently removed this parameter from their fine-tuning API. We found that performance of models fine-tuned on short-completion data had a statistically-significant negative quadratic relationship with PLW. Using small values (0.01 - 0.5) of PLW produced better results on multiple-choice and short-generation benchmarks (outperforming models fine-tuned on long-completion data) while large values (~ 1.0) of PLW produced better results on long-generation benchmarks. We explained this effect and verified its importance through additional experiments. This research serves as a warning to API providers about the importance of providing a PLW parameter for SIFT.

#### Bug 1B: Short-Completion Performance Penalty (CONFIRMED BY LITERATURE)

Our competition task has **extremely short completions** — answers like "42",
"ABC", "blue" inside `\boxed{}`. The prompt-to-completion token ratio is
roughly 20:1 to 50:1.

**Research finding** ([Shi et al., 2024 — "Instruction Fine-Tuning: Does
Prompt Loss Matter?"](https://arxiv.org/html/2401.13586v2/)):

> "Performance of models fine-tuned on our short-completion dataset had a
> **statistically-significant negative quadratic relationship** with PLW
> [prompt loss weight]."

Key data:

| Dataset | Completion/Prompt Ratio | PLW Effect |
|---------|------------------------|------------|
| Short completions | Rg = 0.082 | **Strong negative quadratic** — masking hurts |
| Medium completions | Rg = 0.327 | No significant relationship |
| Long completions | Rg = 7.83 | No significant relationship |

**The optimal prompt loss weight for short completions is NOT zero.** It is
approximately **0.1** (PLW = 0.1 means 10% weight on prompt tokens). Pure
completion-only loss (PLW = 0.0) is specifically the worst configuration
for short-answer tasks.

**Why:** With very short completions, the model gets almost no gradient signal
per example. The few completion tokens provide insufficient learning signal.
Including some prompt loss acts as a regularizer that prevents the model from
drifting too far from the pretrained weights.
---
Based on the research, the highest-impact change is to STOP using
`completion_only_loss=True` and instead train on the full sequence with a
small prompt loss weight. For our competition's extremely short completions,
this should recover the 0.10 score regression and possibly exceed the
baseline 0.60.
